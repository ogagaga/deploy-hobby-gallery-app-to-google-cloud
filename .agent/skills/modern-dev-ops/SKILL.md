# Modern Dev Ops Skill

このスキルは、プロジェクトの技術スタックを最新の状態に保ちつつ、安定性を維持するための運用ガイドです。

## 1. 依存関係の更新戦略

### 1.1 定期的な更新 (Minor/Patch)
- **頻度**: 週1回または月1回程度
- **コマンド**: `/update-safe` (Workflow)
- **目的**: バグ修正やセキュリティパッチ、小さな機能改善を取り込む。
- **安全性**: `package.json` の `^` (キャレット) や `~` (チルダ) の範囲内で行われるため、基本的に破壊的変更は起きない（はず）。

### 1.2 メジャーバージョンの更新 (Major)
- **頻度**: 必要に応じて（新機能が必要な時、サポート切れが近い時）
- **コマンド**: `npm install package-name@latest` (手動実行)
- **注意点**: 
  - 破壊的変更（Breaking Changes）が含まれる可能性が高い。
  - 公式の移行ガイド（Migration Guide）を必ず参照する。
  - 更新後は必ず全テストを実行し、手動でも主要機能を確認する。

## 2. バージョン固定 (Pinning) の管理

特定のリスクを避けるために、あえてバージョンを固定することがあります。

### 2.1 このプロジェクトでの固定ルール
- **対象**: `prisma`, `@prisma/client`
- **固定バージョン**: `6.19.2`
- **理由**: Prisma v7 以降の破壊的変更により、デプロイ環境 (Google Cloud Build) との整合性が崩れるリスクがあるため。
- **解除条件**: デプロイパイプライン全体を v7 対応に改修する準備ができた時。

### 2.2 固定の方法
`package.json` でバージョン番号の前に記号（`^`, `~`）を付けないことで固定します。
```json
"dependencies": {
  "prisma": "6.19.2",  // 固定
  "react": "^19.0.0"   // 19.x.x の範囲で更新許可
}
```

## 3. 推奨ツールと情報源
- **npm outdated**: 更新が必要なパッケージの確認。
- **Dependabot**: GitHub 上で自動的に更新PRを作成するツール（導入検討推奨）。
- **Release Notes**: 使用している主要ライブラリ（Next.js, Prisma, TailwindCSSなど）のリリースノートを定期的にチェックする。
